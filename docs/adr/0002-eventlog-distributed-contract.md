# ADR 0002：EventLog 分布式契约

- 状态：已采纳（2026-08-11）；M2 实现选择见 [ADR 0011](0011-durable-store-and-trace.md)
- 目标里程碑：M2（Store providers）

## 背景

后台 server 需要支持多副本部署，EventLog 的持久化实现可能基于 MySQL、Redis 或其他共享存储。M0-1 只提供内存参考实现，但公开接口不能预设单进程、单写者或进程内通知等条件。

## M0-1R 的最小契约

1. `append(event, expectedLastSeq?)` 支持可选的乐观并发前置条件。空流的流头是 `-1`；提供的期望值与实际流头不一致时，抛出 `EventLogConflictError`，且不得写入或通知订阅者。持久化实现必须在同一原子操作中完成比较与追加。
2. `read(fromSeq)` 返回从包含性游标开始的、可重复迭代的有限快照。分布式消费者负责持久化游标并重试，以至少一次语义处理事件。
3. `subscribe` 只提供单进程内的便利通知，不承诺跨进程投递。订阅者的同步异常与异步 rejection 均与 append 隔离，并可通过 `onSubscriberError` 回调上报；append 不等待订阅者完成，错误回调自身的失败也不得形成未处理 rejection。

以上契约只收紧接口语义，不选择分布式存储方案。

## 待决问题与候选方案

| 问题              | 候选方案                                                         | M2 需要验证的性质            |
| ----------------- | ---------------------------------------------------------------- | ---------------------------- |
| 跨副本 `seq` 分配 | 数据库事务内按流更新；Redis Lua/原子计数；租约下的单写者         | 单调性、跳号策略、故障恢复   |
| 并发写入仲裁      | 基于 `expectedLastSeq` 的 CAS；短期租约；队列串行化              | 冲突可观测性、公平性、尾延迟 |
| 至少一次消费      | 消费者独立持久化游标；存储侧消费组；外部消息总线                 | 重复投递、回压、游标恢复     |
| 重复事件处理      | 消费者按 `(tenantId, sessionId, seq)` 幂等；追加侧引入独立幂等键 | 重试安全、保留周期、索引成本 |
| 读取一致性        | 主库读取；具备读己之写保证的副本；显式一致性级别                 | 复制延迟、快照边界、可移植性 |

## 本 ADR 不决定

- 不选择 MySQL、Redis 或消息总线作为默认实现。
- 不定义租约协议、单写者选举或跨副本 `seq` 算法。
- 不实现消费组、幂等键、游标存储或投递后台任务。
- 不改变 M0-1 的事件 Schema、compaction 策略或 SnapshotStore 契约。

上述选择由 ADR 0011 给出本项目的 M2 方案；本 ADR 的公共 EventLog 契约保持不变。
