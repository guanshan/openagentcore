# ADR 0003：未完成工具调用的恢复语义

- 状态：已采纳（2026-08-11）
- 目标里程碑：M0-2（Agent Loop）

## 背景

`AgentLoop` 在工具执行前后可能崩溃。若事件流以 `tool.call` 结束，系统无法仅凭事件判断工具尚未执行，还是工具已经产生副作用但 `tool.result` 尚未写入。恢复流程必须保留这种不确定性，避免误报 `exactly-once` 语义。

## 决策

1. `tool.call` 是执行工具前持久化的调用意图。只有该事件追加成功后，`AgentLoop` 才能调用工具。同一步的全部调用意图先于任何工具副作用写入；可选 `modelUsage` 复制已完成模型调用的用量，供恢复时闭合 Step 与成本投影。
2. 存在 `tool.call` 但没有匹配的 `tool.result` 时，该调用的结果为未知；恢复流程不得把它直接判定为未执行或执行失败。
3. 恢复流程把结果未知的调用交给 `retry` 策略。默认恢复预算为 1 次，即不重新执行结果未知的调用；只有显式配置才允许重试。策略不重试时追加符合 L0 Schema 的结构化失败 `tool.result`，并按 [ADR 0004](0004-tool-failure-feedback.md) 的动作决定回喂或终止 turn。
4. 重新执行复用原 `callId`，不再追加 `tool.call`。`AgentLoop` 通过 `ToolExecutionContext.callId` 把该标识传给工具；支持幂等操作的工具与适配器应将其用作幂等键。
5. 工具执行整体采用 `at-least-once` 语义，不承诺 `exactly-once`。即使事件流中只有一个 `tool.call`，崩溃后的重新执行仍可能重复外部副作用。

## 后果

- 恢复后的事件流不会因重试产生重复的调用意图，`callId` 在原执行与恢复执行之间保持稳定。
- 无副作用或按 `callId` 实现幂等的工具可以安全重试；其他工具必须通过 `retry` 策略显式选择风险。
- `tool.result` 只表示内核最终记录的处置结果，不能证明外部系统只执行过一次操作。

## 本 ADR 不决定

- 不提供 `exactly-once` 工具执行语义。
- 不定义跨进程或多副本之间的恢复归属、租约与并发仲裁。
- 不实现持久化幂等记录；相关机制在 M2 结合 Store provider 决定。
